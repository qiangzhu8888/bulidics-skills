# 既存コード・データとの連携

## 移植

Reactカード見本は`assets/components/ExhibitorCard.tsx`と`aimeet-ui.css`。既存Routerへリンクを差し替え、既存のお気に入り状態・イベント別ID・i18nをpropsへ接続する。カードの例だけで一覧全体の機能が揃ったと判断しない。

参照HTMLは見た目とブラウザローカル操作の見本であり、本番実装ではない。静的JSON、ローカル保存、外部誘導を既存API/認証済み機能へ接続する。見本データをフォールバックとして実データの代わりに見せない。エラーはエラーとして伝える。

## API

この会話で確認した一覧APIの形は`{items, hasMore, nextCursor}`。各項目には`id, slug, companyName, companyNameKana, boothNumber, categories, category, logoUrl, exhibitionContent`等がある。対象API・型定義を毎回確認し、すべてのイベントで同一と仮定しない。

- `limit=200`を全件取得の保証として扱わない。
- 対象APIがcursor方式なら、`hasMore`と`nextCursor`で続きへ進む。繰り返しcursor、無限取得、重複IDを処理する。
- 認証済み既存クライアント・キャッシュ・サーバー側検索を優先し、画面再描画のたびに全ページを取り直さない。
- 公開条件・権限はバックエンドの契約で保証する。フロントだけの非表示で機密を保護しない。
- 検索をクライアントで行う場合は検索対象全件を確保するか、取得済み範囲であることを明確にする。サーバー検索なら総件数もその応答に従う。
- 空データ、部分取得、失敗、再試行時に表示件数が誤らないようにする。
- URLには許可するHTTP(S)のみを使用し、新規タブへ開くリンクは適切なrelを付ける。入力文字列をHTMLに挿入しない。
- CORS失敗に対してブラウザ保護やWAFを無効化しない。既存のAPI経路・サーバー側構成で解決する。

## localhost

ユーザー端末、開発コンテナ、クラウドのlocalhostは異なる。必要なら既存の接続済みブラウザ/開発環境で確認する。アクセスできない場合は接続不能と表示崩れを区別する。HTML/CSSの変更とコード上の確認を進め、未実施の画面検証を明記する。
