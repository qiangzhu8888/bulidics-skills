# AiMeet UIデザイン

日本語で進行・報告する。今回の会話で作成した出展者一覧・詳細のデザインを再利用する。曖昧な「おしゃれ」の解釈だけで実装を進めず、同梱見本の構図・寸法・情報階層を基準にする。

## 必ず読む資料

1. 着手時に [design-system.md](references/design-system.md) を読む。
2. 一覧には [list-page.md](references/list-page.md)、詳細には [detail-page.md](references/detail-page.md) を読む。
3. データを接続する際に [integration.md](references/integration.md) を読む。
4. 完了前に [visual-qa.md](references/visual-qa.md) を読む。

## 完成見本と部品

- `assets/reference/index.html`：一覧の実行可能な見本。
- `assets/reference/exhibitor.html?slug=demo-01`：詳細の実行可能な見本。
- `assets/reference/guide.css`：今回の一覧の基準CSS。詳細用CSSは詳細HTML内にある。
- `assets/reference/exhibitors.json`：明示的な架空データ。データ構造・欠損・長い社名の見本に限って使う。
- `assets/components/ExhibitorCard.tsx` と `assets/components/aimeet-ui.css`：Reactへの移植用カードとスコープ付きCSS。

見本はHTML/CSSの具体値が一次資料。既存サイトの実装方式に合わせて移植し、静的ページに丸ごと置換しない。見本の架空データ・イベント名・保存先・デモ用リンクを実システムに持ち込まない。

## 実行手順

### 1. 現在の実装を把握する

- 対象URL、イベントID、ルート、コンポーネント、スタイル、使用フレームワークを確認する。
- `AGENTS.md` 等のプロジェクト指示に従う。既存の状態管理、認証、翻訳、API、分析イベントを調べる。
- 既存ページと完成見本を同じ画面幅で確認する。ユーザー提供のlocalhostは、接続先の環境を確認してからアクセスする。こちらのlocalhostと同一だと仮定しない。
- 参照サイトが非公開・閲覧不能でも同梱HTML/CSSを使用する。ブラウザやソースが利用不能なら確認範囲を明示し、取得できるソースから進める。見ていない画面を確認済みと報告しない。

### 2. 差分を具体化する

対象ページについて、最大幅・左右余白・カラム幅・列数・検索高さ・カード画像領域・文字サイズ・行間を見本と照合する。親レイアウトやCSS競合まで追う。色だけの変更で終えない。

特別な指定がなければアイボリー＋白＋深い赤の同梱テーマを採用する。ユーザー指定のブランドテーマや既存イベントのテーマ設定がある場合はそれを優先し、構図・寸法・情報階層を維持する。

### 3. 実装する

- 一覧は「検索 → 条件 → 件数 → 出展者」の順で探しやすくする。
- 詳細は「企業名 → 出展内容 → 小間番号・次の操作」を把握しやすくする。
- Reactでは型付きデータと既存のRouter/Linkを使う。Vue等では同じ構造とトークンへ移植する。実プロジェクトに合わせた再利用可能な部品へ分割する。
- CSSをページのルートクラス等にスコープ化する。見本の`body`・`header`・`button`等のグローバルCSSをアプリ全体へそのまま適用しない。
- 実データと既存機能を維持する。未実装の操作・架空の推薦・マッチング点数・写真・会社情報を生成しない。
- 未登録情報の大きな空欄を省き、欠損に合わせてレイアウトを調整する。
- 小さな変更は必要な確認に絞り、新たな依存関係や無関係な改修を増やさない。

### 4. 実画面で検証・修正する

利用環境が対応するブラウザ操作手段で、基準見本と対象を同一幅で比較する。利用環境固有のプレビュー起動・ブラウザ操作ルールを優先する。Sitesで制作・公開する場合はSitesスキルも使用する。

可能なら1440px・768px・390pxで確認する。画面幅を設定できない環境では、その検証が未実施であることを明記する。スクリーンショットを撮っただけで動作確認済みにしない。

同梱CSS・HTMLの具体値と差を比較して、構図 → カード寸法 → 文字・余白 → 色・装飾の順に修正する。機能確認の詳細はQA資料に従う。

### 5. 仕上げて報告する

変更点、維持した主要機能、確認した画面幅・操作、残る制約を簡潔に報告する。環境が対応するときは実画面を提示する。作成・検証の依頼だけから既存本番サイトへのデプロイを推定しない。公開を含む依頼やSitesの適用ワークフローには従う。

## 使用例

- 「AiMeet UIデザインで、dm-summit-2026の出展者一覧を見本通りに整えて。既存機能は維持して」
- 「この出展者詳細を、画像なしでもきれいなデザインにして」
- 「カードを押しても移動しない問題も直して、PCとスマホで確認して」

## 完了の基準

見本に沿ったレイアウト、実データの正確性、既存機能、欠損・エラー状態、アクセシビリティを満たす。操作できないダミー部品を本番の完成UIとして残さない。取得不能・未検証項目を隠さない。
